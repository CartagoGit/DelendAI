# x01089 — The rehearsal runs for a pull request whose own diff touches the integration code, not for every push that merged the integration branch in, and a refused forge call says why

## goal

The rehearsal workflow is triggered by `pull_request` into the integration branch with the integration code paths, so GitHub filters on the pull request's own diff against its base, instead of by `push` to `delendai/pr/**`, whose path filter compares against the previous push and so counts every file a merge of develop brought in. A forge call land makes that GitHub answers with an error keeps GitHub's own message in the thrown error, so a 403 says whether it is a rate limit or a permission.

## why

Measured 2026-11-17 20:13-20:44 UTC: five rehearsal runs started on push (runs for f00809-S1-g2, x01058-S2-g1, x00980-S1-g1, x01063-all-g2, x01067-all-g1) after each publication merged origin/develop in; `git diff --name-only origin/develop...<pr>` lists 0 files under plugins/integration/ for x01067-all-g1 and x00980-S1-g1, so the rehearsal ran for changes that do not touch the code it tests. Each run plays 11 scenarios acting as the integrator's App identity. From 20:41 UTC every land pass on develop failed with `GET branches/develop answered 403` (runs 44172012898 to 44173936448), so the integrator stopped merging; the error carries no message, so whether the 403 is the installation's rate limit or something else cannot be read from the run. The trigger is rendered by plugins/integration/src/lib/services/rehearsal-ci-workflow.helper.ts renderRehearsalWorkflow (the `push:` block, branches `${namespace}/pr/**`, paths codePaths); `.github/workflows/rehearsal.yml` is generated from it. GitHub documents that a pull_request paths filter is evaluated against the pull request's diff to its base (three-dot), and a push paths filter against the before sha of the push. The forge errors are thrown in packages/core/src/lib/integration/land/github-land-forge.service.ts (`call` returns `{ status, body: undefined }` for a non-zero gh exit, discarding gh's stderr; `ok` line ~90 and integrationTip line ~160 throw `GET <path> answered <status>`).

## non-goals

- Giving the rehearsal an identity or API budget of its own.
- Classifying or retrying a rate limit: measured first, from the message this fix keeps.
