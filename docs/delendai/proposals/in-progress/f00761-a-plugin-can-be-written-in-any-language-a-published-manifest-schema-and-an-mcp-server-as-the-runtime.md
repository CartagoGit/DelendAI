# f00761 — a plugin can be written in any language: a published manifest schema, and an MCP server as the runtime

## goal

A plugin author who does not write TypeScript declares the plugin in a JSON manifest validated against a schema delendai publishes, ships it as an MCP server in any language, and delendai serves it lazily with the same permissions, catalog and activation as a TypeScript plugin.

## why

Extracted from f00542 S1 and S2 (which stay paused). The owner asks that delendai be agnostic of runtime and language. f00542 proposed validators in six languages and a runtime adapter per language. Most of that already has a smaller answer in the code:

1. **The runtime exists.** `plugins/external-mcps` (f00550) fronts any MCP server (capability registry, project contract, verify), and an MCP server can be written in any language. What it does not give is a delendai plugin: no manifest, no permissions, no entry in the lazy catalog, no agent roles.
2. **The manifest is TypeScript only.** `packages/core/src/lib/manifest/define-plugin-manifest.ts` defines it as a zod schema, reachable only by importing `@delendai/core`. No JSON Schema of it is published, unlike the configuration's (`packages/core/schema/delendai.config.schema.json`, `bun run config:schema`).

## non-goals

- Validators written in other languages: a published JSON Schema is validated by every language's existing tooling.
- Per-language runtime adapters, transports other than MCP, plugin signing (f00542 S2, S7 and S8 stay paused).

- acceptance:

  - Every first-party plugin's manifest, serialised to JSON, validates against the zod schema it was generated from.
  - Note for S2: the schema requires a `@delendai/` package name, which fits first-party plugins only; a third-party server's manifest needs its own variant without that constraint, and the permissions it declares need a decision on how they are enforced through the call proxy.

### S2 — An MCP server with a manifest is a plugin

- **Status**: pending
- **Files**:
  - `plugins/external-mcps/src/lib/catalog/manifest-plugin.service.ts`
  - `packages/core/src/lib/plugins/managed-lazy-local-catalog.service.ts`
- **Gate**: type
- acceptance:
  - A `delendai.plugin.json` beside an MCP server's command, valid against the schema, makes that server a plugin: its tools are in the lazy catalog, its declared permissions are enforced, and its agent roles are written like a TypeScript plugin's.
  - A manifest that does not validate is refused at start with the schema's own error path.

- TypeScript plugins are unchanged.
