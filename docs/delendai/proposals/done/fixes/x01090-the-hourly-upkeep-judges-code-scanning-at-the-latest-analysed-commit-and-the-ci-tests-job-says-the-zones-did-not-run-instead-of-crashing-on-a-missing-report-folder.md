# x01090 — The hourly upkeep judges code scanning at the latest analysed commit, and the CI tests job says the zones did not run instead of crashing on a missing report folder

## goal

Two false reds in the integration flow end. (1) The upkeep's `promotion-alerts` step no longer fails because CodeQL has not yet analysed a develop tip that merged minutes earlier: with `--latest-analysed` it judges the open alerts at the latest analysed commit and names it; the release gate keeps requiring an analysis of the exact tip. (2) The CI `tests` job, when `plan-tests` or the zones were cancelled or skipped, fails with one line saying the zones did not run and the run must be re-run, instead of crashing with `ENOENT: scandir .vitest-reports`.

## why

Measured 2026-11-17. (1) Upkeep run 44188822302 (22:19 UTC): `✖ promotion-alerts: no completed code scanning analysis covers develop at af5f24fbeac7 (latest is 76a6d0477d95)`: develop had moved by one merge (#1894) minutes earlier and its CodeQL run had not finished. tools/scripts/forge/promotion-alerts.script.ts coverageRefusal (line ~97) refuses whenever the latest analysis does not cover the tip; that is right for a promotion (.github/workflows/release-pr-gate.yml:67) and wrong for an hourly watch of a branch that merges several times an hour. The upkeep step is rendered from tools/scripts/forge/land-workflow.script.ts REPO_VALUES.upkeep into .github/workflows/land.yml. (2) CI run 44172437853 on #1958: `plan-tests` was cancelled during its Setup repo step; tests-zone was skipped; the `tests` job's step 'Check whether the plan ran any zone' (.github/workflows/ci.yml ~line 792) only handles ZONES_RESULT=failure and a plan with no zone, so the run fell through to the merge and crashed `ENOENT: scandir .vitest-reports`, which reads as a test failure of the pull request.

## non-goals

- Changing which alerts fail the promotion.
- Making plan-tests faster.
