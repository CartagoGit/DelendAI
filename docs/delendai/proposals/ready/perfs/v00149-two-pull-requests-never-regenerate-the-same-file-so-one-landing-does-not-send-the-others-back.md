# v00149 — Two pull requests never regenerate the same file, so one landing does not send the others back

## goal

One pull request landing sends no other one back for a fresh run just because both regenerated the same derived file.

## why

Of the last 40 merged pull requests (2026-10-28/29), 31 took at least one merge of develop after they were opened and 13 took three or more. Each merge starts the whole CI run again (13-51 runner-minutes). The queue brings a candidate forward as soon as develop changes a file the candidate changes too (`candidate-disposition.ts`). The files most candidates share are the derived ones, regenerated by whoever touches their sources: `docs/delendai/TOKEN-BUDGETS.md`, `preset-metadata.generated.ts`, `managed-lazy-catalog.generated.ts`, the per-workspace `AGENT.md`, the agent catalog. Ten of the forty touched one directly. A derived file shared by every change turns independent pull requests into a chain.

## non-goals

- Bringing candidates forward less carefully. A real overlap on a hand-written file is still brought forward while it is fresh.
- Dropping a derived file that a person or a published page reads.

## slices

- global_gate: type

### S1 — Which shared files send candidates back is measured
- **Status**: pending
- **Files**: `tools/scripts/forge/candidate-overlap-report.script.ts`, `tools/scripts/forge/candidate-overlap-report.script.spec.ts`
- **Gate**: type
- acceptance:
  - "`candidate-overlap-report.script.ts` lists, over the merged pull requests since a date, each file whose change on develop brought an open candidate forward, how often, and whether it is derived (a `*.generated.*`, an `AGENT.md`, or a file `gen:all` writes), so the next slices act on the measured offenders (candidate-overlap-report.script.spec.ts)."

### S2 — A derived file is not an overlap
- **Status**: pending
- **Files**: `tools/scripts/forge/candidate-disposition.ts`, `tools/scripts/forge/candidate-disposition.spec.ts`
- **Gate**: type
- acceptance:
  - "A candidate whose only files in common with develop's new commits are derived ones is not brought forward for the overlap; it is brought forward only when GitHub reports it conflicting or its merge result is red, and then regenerated (candidate-disposition.spec.ts)."

### S3 — The most shared derived files are split by their source or generated where they are used
- **Status**: pending
- **Files**: `tools/scripts/gen-all.script.ts`, `docs/delendai/TOKEN-BUDGETS.md`
- **Gate**: type
- acceptance:
  - "Each derived file S1 measured as the top offenders is either split so a change to one source rewrites only that source's part, or no longer committed and generated by the step that uses it, with the drift check following it; S1's report run again over a week of merges after it shows none of them."

## acceptance

- `candidate-overlap-report.script.ts` lists, over the merged pull requests since a date, each file whose change on develop brought an open candidate forward, how often, and whether it is derived (a `*.generated.*`, an `AGENT.md`, or a file `gen:all` writes), so the next slices act on the measured offenders (candidate-overlap-report.script.spec.ts).
- A candidate whose only files in common with develop's new commits are derived ones is not brought forward for the overlap; it is brought forward only when GitHub reports it conflicting or its merge result is red, and then regenerated (candidate-disposition.spec.ts).
- Each derived file S1 measured as the top offenders is either split so a change to one source rewrites only that source's part, or no longer committed and generated by the step that uses it, with the drift check following it; S1's report run again over a week of merges after it shows none of them.
