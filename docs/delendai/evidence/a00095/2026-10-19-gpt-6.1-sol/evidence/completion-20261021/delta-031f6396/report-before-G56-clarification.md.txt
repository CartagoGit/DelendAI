## What the delta fixes

An accepted account can now be explicitly enabled for unattended work during the offer flow. `offerFoundAccounts` asks the second question only after the first answer is true and writes `permittedAutomation` true only for an explicit second yes (`account-offer-flow.service.ts:71-85`). Omitting the callback still leaves automation off. CLI offer and interactive init share that flow (`accounts.command.ts:37-64`; `init-accounts-offer.service.ts:28-43`). `--yes` alone leaves automation off; `--yes --allow-automation` enables it for newly accepted accounts. Those flags apply to newly offered accounts, not an implicit bulk rewrite of held accounts.

`delendai accounts automation <id> on|off` now changes one account in the personal project layer (`accounts.command.ts:71-92`; core flow101-116). The writer performs read/check/update under a per-file mutex with contention waiting, preserves other layer fields, refuses malformed current configuration and missing personal accounts, and writes with the private file mode (`personal-layer-writer.service.ts:125-169`). Repeating the same state reports changed:false. Shared accounts are deliberately refused, with instructions for the shared configuration; this is an explicit non-goal of f00779 rather than a missing implementation of its personal-account promise. Bad CLI usage returns2 and caught missing-account errors3; the command currently maps any thrown update error to NOT_FOUND, so a filesystem failure is not distinguished from an unknown account. This is a bounded error-classification limitation, not evidence of a reproduced failed write.

The guide now opens with offer and automation commands, and the core CLI barrel exports the new setter. A top comment in account-offer-flow still says every account stays closed to unattended work; it is stale against the explicit second-answer behavior, while the actual function documentation and tests describe the new contract.

**Local validation: 2 specs / 9 tests passed** against an extracted031f snapshot with source aliases: core account-offers and CLI init-offer. Core uses injected discoveries and explicit temporary personalRoot; init uses fake prompt/offer ports. Only local temporary Git init and trivial local printf/exit commands ran. Global/system Git config was disabled and fetch was denied. No actual client discovery, provider status command, credentials, provider invocation or paid work ran. CLI command/registry specs were inspected in the diff but not executed, because their other cases can invoke real client discovery; the exit-code result is therefore static here. `tests-output.log` retains the clean run.
