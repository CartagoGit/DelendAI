## C3 — invented slice names

**Historical claim confirmed for its old snapshot; the literal current claim that enter accepts every slice is now too broad.** `packages/core/src/lib/work-units/work-unit-enter.service.ts:236–237` invokes the new `unitRefusal` before selecting/creating a work ref. `work-unit-generation.service.ts:370–380` composes ambiguity refusal, occupied-proposal check and `undeclaredSlice`. The public engine routes enter through this function at `work-unit.service.ts:99–102`.

The new `declared-slice.service.ts:20–32` reads heading IDs from a proposal committed at the selected integration base. `:62–66` adds declarations from locally known refs for that proposal. With a known integrated proposal containing recognized slices, a new unknown slice returns refusal naming declared IDs (`:67–70`). The added spec explicitly covers the historical concatenated `S11S12S13S14` name (`tests/src/lib/work-units/declared-slice.service.spec.ts:65–75`), plus normal declarations, all/batch/unwritten cases and already existing units (`:77–98`). The broader enter spec demonstrates a slice newly declared in an unlanded unit is accepted (`reviewed-proposal.service.spec.ts:154–177`).

**This is a scoped prevention improvement, not retroactive invalidation of existing units.** `all` and `batch` are exempt (`declared-slice:49–50`). An absent proposal, unreadable/missing integration source or proposal with zero recognized slice headings is allowed (`:51–54`); a pre-existing locally known ref matching the requested proposal/slice is grandfathered (`:55–60`). Those refs are not restricted to a work/publication namespace in this function. The recognizer is exactly `^###\\s+(S\\d+[a-z]?)\\b` (`:17`), not a complete Markdown/proposal semantic parser. The check uses fetched/local Git knowledge, with `integrationBase` choosing local or remote-tracking integration commit under policy (`work-unit-shared.service.ts:182–206`), not a live global declaration registry.

Suggested consensus wording: **C3's old behavior has been partly corrected in 031f6396: new undeclared slices are refused for known sliced proposals, with explicit legacy, all/batch and missing-document exemptions.** No public enter was executed in this continuation.

## C5 — occupied proposal IDs and multi-proposal creation units

**A concrete entry check now rejects known occupied IDs for explicit create units; the entire C5 claim is not closed.** `taken-proposal-id.service.ts:25–58` applies only to `--kind=create` (`:32`). It checks the integration tree (`:33–35`) and locally known work/publication refs, including remote-tracking refs, belonging to another agent (`:37–50`), then refuses with allocation/re-entry guidance (`:51–57`). It runs through the same public enter chain above before creation of a work ref. The specs cover integrated f00776, another agent's remote-tracking work ref, a local publication, own units, free IDs and implement-kind exemption (`taken-proposal-id.service.spec.ts:54–135`).

**The check is not an ID allocator or atomic cross-agent reservation.** It calls only reads; it neither acquires the allocator's counter reservation nor performs a compare-and-create of a shared proposal-ID claim. Entry serialization is keyed by agent, kind, proposal and slice (`work-unit-enter.service.ts:113–118`); its work-ref file lock uses that same key (`:139–149`). Different agents therefore do not gain a global proposal-ID mutex from this entry lock. Remote-tracking refs mean already fetched knowledge, not a fresh ls-remote of all other creation units in this checker. These source properties limit the guarantee; no simultaneous-create failure was executed or claimed here.

The delta does not enforce one proposal body per creation unit, require an allocated nonempty body, or prevent previously reserved TODO stubs from being abandoned. The declared-slice gate concerns unit names, not counting the proposals a unit edits. C5 combines known-ID entry mistakes, allocator/reservation workflow and multi-proposal units; only the first has a new directly observed guard. Existing own units and non-create entry remain intentionally allowed.

Suggested consensus wording: **Known occupied create IDs are now refused through the canonical enter path. Atomic allocation with a body, abandoned placeholder handling and one-proposal-per-unit constraints remain distinct questions; the new read-before-create guard does not prove them solved.**

## C7 — overlapping work and stranded publication

**The cited historical coexistence/47-commit count remains an observation of that time; it was not remeasured. The new delta does not establish universal one-agent-per-slice or integration durability.** The only changed behavior in `unit-push.service.ts` is refusal-line selection: `failureLineOf` (`:25–52`) prioritizes the last check verdict, then last failure line, then last output. Its return is used at `:99–104`. The added specs cover a hook command followed by the actual failed check and Git's generic final error (`unit-push.service.spec.ts:151–178`). This makes an unsuccessful durability push actionable instead of blaming the first command printed by the hook. It neither retries/merges a refused push nor integrates the publication.

The existing push executes an ordinary, non-forced same-name branch push (`unit-push.service.ts:75–93`) and catches/report refusal (`:94–105`). The guard calls it and prints the explicit committed-locally warning plus repair command (`packages/cli/src/commands/guard.command.ts:301–315`). A refused push can therefore still leave local-only work; descriptive improvement is not a delivery guarantee.

Existing overlap prevention predates this delta: enter checks other agents' holders (`work-unit-enter.service.ts:203–223`), chooses generations (`:224–235`), and reserves a new implement slice on the forge (`:315–329`). Those are material mitigations and refute an unqualified statement that the code performs no coordination. However review units intentionally do not hold slices (`slice-holders.service.ts:23–24,68`), `--alongside` deliberately skips the entry holder and forge reservation guards (`enter:203,318`), existing-unit paths return before new reservation (`:263–304`), and unavailable forge reservation does not refuse (`slice-reservation.service.ts:225`). Same-agent session/generation coordination has further controls (`work-unit-generation.service.ts:120–223`), not an unconditional ban on all second units. The holder and reservation source files are unchanged between the two snapshots (diff exit 0). No race/remote outage was executed.

Suggested consensus wording: **C7 remains a historical coordination/durability risk with existing bounded prevention. 031f6396 improves push-refusal diagnosis; it does not by itself enforce per-reviewer task allocation or ensure every WIP lands before quota exhaustion.** Separate semantic overlap from review coexistence and deliberate alongside work.
