## Scope and assessment

This family implements concrete workflow behavior: proposal completeness, review attribution and independence, claims and forge reservations, review queue paging, per-slice delivery evidence, lifecycle results, database diagnostics/projection maintenance, context compilation, incident-draft policy and checkpoint advisories. Most pure decision helpers expose injectable ports; effectful adapters are relatively narrow. Several earlier manual divergences have been consolidated: brace-aware declared-file parsing, caller checkout mapping, one review claim/reservation mechanism, one interface for identity-journal reads and explicit parity classifications.

The family does not register tools independently: its effects and output contracts must be interpreted with the named tool callers, not inferred from helper names. Close-plan and close-slice services construct lifecycle envelopes; they do not independently prove the transition happened. Context compilation uses local search/document/summary ports, scope filtering, deterministic band priority and an approximate character/4 budget; the two existing compiler specs verify bounded emitted items and no unnecessary summary calls when scope excludes the document. It does not issue an LLM call. Its token accounting is an estimate rather than a tokenizer measurement, and the task and structural envelope are outside item-token totals. No provider costs were measured.

Review services derive maker attribution from project work-ref shapes and Git notes, support explicit unrecorded attribution, keep a shared local submitter identity journal and distinguish per-instance from per-model independence through a common helper. Reservations use remote compare-and-swap on named refs and lease expiration rather than assuming a local empty claim commit prevents distributed races. That is genuine remote mutation capability in ordinary product operation; this audit used only a fake Git runner and never invoked those operations. Failures and unsupported/missing repository facts frequently fall back to unavailable or undefined; availability is intentionally separate from proof. The exact meaning of those fallbacks must remain visible in callers.

Projection services preserve Markdown authority and make SQL/JSON parity explicit. Refresh failures report fallback rather than falsely saying the projection was refreshed. Doctor opens read-only and distinguishes an unopenable derived database from a corrupt database; integrity and FK checks do not assume a missing DB is healthy. Rebuild stages through the reconcile tool; verification copies a proposals tree into a temporary execution root and cleans it in finally. No application DB was opened during this review. Metadata and raw SQL can still be inconsistent at producer/consumer seams, as the quarantine path trace demonstrates.

The cost of queue presentation has useful boundaries: compact list views omit per-slice evidence and detail is requested for one proposal; pagination and changedSinceTruncated disclose incomplete lists; delivery history caps at5,000 first-parent entries. However buildReviewQueue reads/derives the backlog, delivery history and drift before pageOfQueue slices its result. A small response page therefore does not bound Git/I/O work. Many calls within proposal/slice/candidate loops are sequential; review drift also loads commit and path facts per proposal. This is a code-derived cost observation, not an end-to-end latency result or proof of a production bottleneck.

**Provisional services-family score: 6/10.** The functionality is substantial, the evidence model is more explicit than a status-only document workflow, and local seams are testable. The score is lowered by mismatched quarantine path bases, mixed maker attribution and significant overlapping legacy/new helper paths. Root must combine this with its other proposals-family findings before assigning a plugin-wide score. Splitting a behavior into many one-purpose modules alone is not evidence of better correctness; cross-module data contracts matter more.

## Findings and bounded candidates

**G61-PROP-SVC01, P2, statically confirmed:** quarantine repair resolves proposal-relative paths against workspaceRoot. The main reconcile collector stores relative(proposalsDirAbs, full). Preflight excludes malformed/vocabulary/duplicate entries; after successful accepted-set promotion, recordSetAsideFiles writes excluded files with a frontmatter fence into pending quarantine, keeping the same path string. Repair re-parse resolves that string against workspaceRoot. For the default nested directory, in-progress/x.md is looked up under /workspace/in-progress instead of /workspace/docs/delendai/proposals/in-progress. Direct staging and promotion also preserve paths without prepending anything. The complete chain is in caller-evidence.log. This corroborates the coordinator's current candidate and must be aliased to its canonical finding, not counted twice. No actual DB repair was executed.

**G61-PROP-SVC02, P3, probable diagnostic-policy defect:** a current successful reconciliation does not clear a stale warning from any older successful run. The exact production predicate on an in-memory synthetic SQL table with two successful runs, old and new, returns1. Default doctor includes the check and healthy requires every check to be ok. This establishes the behavior; whether historical old completed runs should intentionally make current health unhealthy is a product-policy judgment, so it is not labeled a conclusively broken contract. A latest-relevant-run freshness metric would be more actionable, with incomplete historical runs reported separately.

**G61-PROP-SVC03, P2, confirmed helper/caller attribution defect:** complete maker notes [submitter, other] produce carriedFrom=other because the submitter is filtered before the cardinality test. The submit caller then writes other as implementer and claims every commit came from the other maker. The production helper was executed with a fully fake Git runner. Important limit: the submit identity journal still records the actual submitter; the approval helper refuses that submitter when the journal is present. A missing journal falls back to the incorrectly recorded implementer at that helper, while queue delivery candidates and other authoring gates may supply further protection. This review proves wrong attribution, not a universal independent-approval bypass or an executed full review-tool exploit.

A separate observed helper mismatch remains unindexed: touchesPublicContracts misses repo-relative packages/core/src/lib/plugins/preset-catalog.ts but recognizes /ws/packages/core/src/lib/plugins/preset-catalog.ts due to a leading slash in endsWith. The production queue caller currently supplies affectedPaths:[] and affectsPublishedOutputSchema:false, so the isolated mismatch does not establish a currently reachable queue decision for that path. Keep the caller contract gap explicit rather than claiming demonstrated automated public-contract edits.

## Negative hypotheses and limits

Manual evidence declarations are not classified as weak validation merely because agents provide them. The transition-evidence tests explicitly allow future timestamps for clock skew, so this review does not invent an unsupported no-future-timestamp contract. Unrecorded delivery does not mean the product promises verified independence; source explicitly says it cannot establish it and names owner closure. Retired slices deliberately owe no implementation/review evidence. Parked lifecycle states deliberately have no forward rank. SQL search values are parameterized; FTS query syntax is not shell execution. The context compiler's cached-summary preference is deliberate and tested. Missing/corrupt optional caches returning unavailable are not automatically silent data corruption.

Not all real Git history shapes, distributed reservation failures, multi-process journals, quarantine migrations/repair, full application DB diagnostics or host integrations were executed. Existing stage/promotion/approval gates outside this family were traced only as needed and remain owned by the other readers. `findings.json` contains full evidence fields; `commands.md` documents execution boundaries and the post-execution Bun diagnostic retained in probe-output.log. The separate clean Vitest run passed16tests. No source edits, claims, provider calls, credentials or external mutations were made.
