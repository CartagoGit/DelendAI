## Contracts and composition

All 81 contracts files were read in full. The 22 lock-family files were read in the earlier batch. The plugin entrypoint was then read in full (1–1461). API/adoption/resources/skills/surface and the returns/persistence modules were read next. Comments containing old tool counts are not used as live catalog evidence.

- **Rejected bypass hypothesis:** the public schema advertises `skipDfaForPlanClosure` (`contracts/proposal-transition-input.contract.ts:61`), but the actually registered handler (`tools/proposal-transition.tool.ts:2213–2219`) goes through `runProposalTransitionCompat`. Its `stripPublicOnlyFields` explicitly removes the key before parsing (`tools/proposal-transition.compat.ts:79–108`). Therefore the public handler does not grant this skip. Direct internal calls retain it deliberately. Schema text is confusing but not evidence of a public bypass.
- **Configuration mismatch candidate:** `index.ts:995–1018` builds the real transition registration without forwarding `parsedOptions.data.requireValidateEvidence`, even though `PROPOSALS_OPTIONS_SCHEMA` declares it at `index.ts:254–258` and the tool option documents false as a supported adopter choice (`tools/proposal-transition.tool.ts:253–263`). The effective gate is `options.requireValidateEvidence !== false` at `:1142–1182`, so this public setting cannot turn that gate off through normal composition. Authoring options (`index.ts:657–662`) and auto_work (`:938–944`) do receive it. This is a static, directly resolved composition discrepancy, not an environmental execution result. Assess product intent before changing the invariant that terminal transitions retain a global gate.
- **Detail-level candidate:** the registered proposal_get handler calls `buildSurfaceResponse` (`tools/proposal-get.tool.ts:331–358`). For every detail request it returns `proposal: buildDetailProposal(loaded)`, changing only `level: args.detail ?? normal` (`:289–296`). There is no compact/normal/full dispatch. The plugin contract defines a narrow compact view and `IProposalFullView = IProposalDocument` (`contracts/proposal-view.contract.ts:27–66`) plus three distinct projectors (`:115–168`). A full request therefore gets the same normal detail payload as compact, and neither gets the complete document. No execution performed for this candidate.
- **Read-only contract is not a transitive authority:** `assertReadOnlyCall` (`contracts/interfaces/materializer.interface.ts:206–230`) checks only each immediate dependency for a `.materialize` function; it does not recursively inspect callable behavior. The index source constant explicitly describes on-demand rebuilding in default sql mode. Do not treat the shape guard as proof that every read path is side-effect free. Trace service implementations before assigning a new finding.
- Proposal compact projector alone emits id as title, but the real proposal_get handler overrides title from frontmatter/heading (`proposal-get.tool.ts:102–138`), so a projector-only title finding would be false on the public path.
- History/review path hypothesis rejected: `buildSwarmPaths` actually puts peerReviewLogFile at `<cache>/proposals/peer-review.jsonl`, beside proposalIndexFile (`constants/default-path-layout.constant.ts:35–37`); `loadPeerReviewEntries` uses that directory (`proposal-get.tool.ts:220–223`). Authoring writes the separate legacy journal at :2866–2878 and also records the structured action into scoped.peerReviewLogPathAbs at :2917–2930. The latter matches the reader. Two journal formats are not a missing-history defect.
- Proposal list pagination still loads/parses every indexed file before slicing (`proposal-get.tool.ts:229–285`). Output pagination bounds response count, not total IO work. Cursor is any nonempty string and is passed to parseInt; malformed cursor handling needs a behavioral fixture if promoted. No runtime latency claim is made.
- Transition is not one global transaction: evidence/approval guards and some source writes occur before applyTransition takes the per-file mutex (`proposal-transition.tool.ts:1125–1140`, `:1376–1403`, `:1835`). Inside that mutex it rechecks current status (`:1887–1927`) but does not rerun every preflight against a revision hash. This is bounded source evidence, not a demonstrated concurrent invalid close. Nested source/destination mutexes require core reentrancy analysis before any deadlock claim.
- Work telemetry journal swallows recording failures intentionally (`proposal-work-events.ts:31–56`); the duration recorder is also advisory and catches asynchronous failures (`proposal-transition-duration.ts:94–105`). Do not conflate either with lifecycle persistence guarantees.
- DB wrapper reading: conflicts/diff/verify use `withOkEnvelope`, matching toolOk. Tombstones/quarantine-list are read diagnostics. Rebuild, resurrect and summary-backfill invoke mutating services but their registrations do not declare effects. This is an additional concrete instance of the already-known incomplete effect-metadata family, not yet a new root finding. Their underlying service logic remains outside this reader’s completed scope.
