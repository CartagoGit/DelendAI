## Defectos y límites estáticos

**INT-EX01 P2 — dependencias Compose arrancadas no se liberan.** `compose-args.helper.ts:31` elimina --no-deps con withDependencies:true; `docker-compose.service.ts:113–115` teardown es no-op. --rm elimina contenedor oneoff, no sus servicios dependientes; comentario 'nothing ... released' sólo cierto sin deps. Spec127 comprueba flag únicamente y teardown190 espera cero llamadas, no representa recursos adquiridos. Corrección: seguir dependencias que esta instancia adquirió y liberar sólo esas, o definir lifecycle compartido explícito. No daemon ejecutado.

**INT-EX02 P2 — validación límites se cachea y no se liga a ejecución.** prepare carga parse en this.parsed (`docker-compose:129–136`), chequea requireLimits, pero exec no comprueba resultado/estado ni revalida archivo límites (`79–110`). Incluso secuencia prepare exitosa→archivo alterado→exec pasa la ruta actual a Docker sobre contenido distinto. Consumer puede llamar exec sin prepare; interfaz sólo documenta orden. Corregir contrato state/identidad de config o enforcement por ejecución. Hallazgo estático, sin ensayo.

**INT-EX03 P2 — env de docker-exec no respeta simulación con runner inyectado.** `docker-exec.service.ts:122–127` llama inspectContainerEnvironment que invoca runner.run directamente (`docker-env:25`). dryRun:true evita prepare/exec pero no env. Runner default guardado rechaza lectura en simulación; runner inyectado puede ejecutarla. Defecto consistencia dryRun de biblioteca, no se afirma exploit host ni se realizan pruebas.

PowerShell buildRemoteCommand concatena Set-Location; invocation; exit LASTEXITCODE (`shell-quoting:58–68`): fallo Set-Location no corta comando y puede ejecutarlo en directorio previo. POSIX sí usa&&. Error de fiabilidad pendiente ensayo plataforma.
