# Ficha individual — plugin `gitlab`

Auditor: **gpt-6.1-sol** (Codex). Fecha: 2026-10-19. Snapshot: `514758e783620c8953079be4d71fceccacb3de8b`. La fuente `plugins/gitlab` coincide con `origin/develop` en ese SHA. La revisión se limita a ese snapshot; no se usaron credenciales ni red de GitLab.

## Inventario leído y ejecución

Leí manifiesto, `AGENT.md`, README, `package.json`, entrypoint, configuración, cliente HTTP, adaptador de mutaciones, diagnósticos, todas las funciones y normalizadores de `tools/shared.ts`, adaptadores de registro de tools y las ocho suites. El código de producción suma 4.971 líneas en 18 archivos TypeScript (los adaptadores `*.tool.ts` son reexports). Las pruebas suman 3.617 líneas en ocho archivos. La suite ejecutada desde el checkout compartido fue `bun run --cwd plugins/gitlab test`: 8 archivos y 113 tests aprobados (5,67 s), después de comprobar igualdad de los fuentes de GitLab con el snapshot. Vite imprimió una advertencia de compatibilidad del config loader, sin fallar.

Hay 11 registros MCP de solo lectura por defecto (`context`, `projects`, `issues`, `merge_requests`, `commits`, `refs`, `pipelines`, `jobs`, `artifacts`, `releases`, `deployments`) y cinco herramientas agrupadas de escritura disponibles solo con `allowWrite: true` (`issue_write`, `discussion_write`, `pipeline_write`, `job_write`, `release_write`). Cada registro público tiene esquema de entrada y salida. Las entradas son estrictas, paginación/listas y logs tienen límites, y los resultados normales se normalizan y recortan. Las llamadas de proveedor usan cliente inyectable; toda prueba fue hermética.

## Evaluación por criterio

- **Funcionalidad:** implementación real y amplia del proveedor: proyectos, variables sin valores, issues, MR/discusiones, commits/comparación, pipelines/jobs/logs, artefactos, releases/tags y deployments. Las herramientas no dependen de `plugin-git` ni de checkout local. Sin token el plugin degrada limpiamente a cero tools y conocimiento de configuración. No verifiqué GitLab.com ni un servidor autogestionado real.
- **Contrato MCP:** nombres/descripciones concuerdan con los grupos de funciones; el esquema de salida incluye estados normales, aunque los errores de lectura se serializan como `toolError` con otra forma efectiva, al estilo compartido por el paquete. Los schemas strict evitan parámetros desconocidos. Paginación explícita y topes de 100 elementos. La cobertura existente prueba happy paths, errores, esquemas y opt-in de escrituras. El grupo de escritura requiere confirmación antes de HTTP; el executor común no reintenta mutaciones y escribe recibos de auditoría redactados.
- **Seguridad/aislamiento:** token solo en el entorno y no en contexto, conocimiento, outputs ni recibos; URLs requieren HTTPS y se rechazan IP literal y redes privadas; errores no devuelven headers/tokens. Las mutaciones están desactivadas por defecto. Riesgos confirmados: (1) symlink en un subdirectorio de `pluginTempDir/artifacts` escapa el `safeJoin` léxico y deja que el tool escriba fuera del cache; (2) `maxBytes` limita bytes guardados, no bytes descargados/materializados en memoria. Ambos hallazgos son P2 y tienen reproducciones locales abajo. `safeJoin` también verifica contención léxica, no identidad del destino real.
- **Calidad:** separaciones útiles entre configuración, HTTP, normalización, diagnósticos y mutaciones, además de tests sin servidor real. `shared.ts` concentra schemas, normalizadores y 11 registros en 2.107 líneas, por lo que los cambios y la revisión del contrato son costosos. El timeout tiene una laguna concreta: el temporizador se cancela justo después de recibir cabeceras, antes de consumir cuerpo/buffer. Suite verde no lo detecta.
- **Coste de contexto:** medición de bytes JSON wire por herramienta/tokenizador no disponible en este host y no la infiero de `tools/list` local, cuyo perfil MCP no corresponde al repo. Como señal estática, 11 tools en modo lectura y cinco más optativos; descripciones breves, schemas no triviales, sin duplicación de nombres. Los listados tienen page/perPage máx 100 y los textos principales se recortan por campo. La respuesta/ArrayBuffer HTTP sí se carga entera; no hay presupuesto global de bytes en el cliente. Los 4.971 LOC son coste de mantenimiento, no tokens de definición.
- **Producto:** configuración razonable vía `GITLAB_TOKEN`, `GITLAB_URL` y proyecto default; se acepta alias legacy de token. El error sin token recomienda reiniciar el servidor. La restricción a HTTPS y a hosts no privados bloquea instalaciones GitLab autoalojadas accesibles solo por LAN/IP; README afirma soporte self-managed. Es una incompatibilidad de producto que requiere decidir el modelo de amenaza, no la marco como defecto de seguridad explotable. Mantener los writes en herramientas separadas está bien. Simplificaría partir `shared.ts` por recursos y hacer el límite/stream de cuerpo una política del HTTP client común.

**Nota provisional: 6,5/10.** Buena amplitud funcional y contratos/controles deliberados, con cobertura focal fuerte. Bajan la nota la escritura fuera del cache vía symlink, topes de bytes que solo se aplican tras descarga y timeout incompleto. No puntúo la integración real con GitLab o hosts MCP sin pruebas correspondientes.

## Hallazgos nuevos

### GLAB-01 — P2 — escape del directorio temporal mediante symlink

- **Estado:** confirmado con ejecución local hermética. **Componente:** `gitlab_artifacts`.
- **Ubicación:** `plugins/gitlab/src/lib/tools/shared.ts:822-835` (`safeJoin`, resuelve y compara rutas léxicas); `:1825-1843` (construye subruta por proyecto/job y escribe con `writeFileAtomic`).
- **Esperado:** el tool deposita el archivo solo bajo el directorio de artefactos del plugin, incluso si hay enlaces preexistentes.
- **Real:** `safeJoin` acepta un candidato lexicalmente interior aunque un ancestro sea symlink a otra ubicación. `mkdir` y la escritura siguen el enlace.
- **Reproducción:** `bun evidence/gitlab/repro-artifact-symlink.ts` desde la raíz del snapshot. Crea un cache temporal, enlaza `plugin-cache/artifacts/1` a un directorio temporal exterior y llama al handler real de `gitlab_artifacts` con proyecto `1`, job `7` y nombre `proof.txt`.
- **Resultado:** `{"escapedWrite":true,"escapedPath":"/tmp/gitlab-artifact-audit-…/outside/7/proof.txt","escapedContents":"pwn"}`. No usa red ni datos de usuario. Log: `evidence/gitlab/repro-artifact-symlink.log`.
- **Impacto:** escritura fuera del cache declarado a través de una herramienta documentada como descarga acotada. Requiere que el árbol temporal contenga un symlink, condición posible en workspaces/cache no confiables. Severidad P2 por precondición y alcance de ruta.
- **Causa:** `resolve()`/prefijo textual no siguen componentes symlink; `writeFileAtomic` protege atomicidad, no contención física.
- **Corrección mínima:** crear/abrir ancestros con comprobación sin symlinks y comprobar realpath del padre contra realpath del cache justo antes de escribir (idealmente primitiva contenida compartida con semántica anti-TOCTOU).
- **Regresión:** fixture temporal con symlink hacia afuera; el handler debe rechazarlo y confirmar que no crea ningún archivo fuera. Mantener caso de traversal léxico existente.
- **Confianza:** alta: reproducción con handler registrado y filesystem local.
- **Relación:** nuevo; el test existente `tools.spec.ts` solo cubre nombre `../../secret.zip`, no symlinks.

### GLAB-02 — P2 — timeout no cubre el cuerpo de la respuesta

- **Estado:** confirmado por reproducción local. **Componente:** cliente HTTP GitLab.
- **Ubicación:** `plugins/gitlab/src/lib/client.ts:535-548` limpia el temporizador tras recibir headers; `:549-570` lee después error-body o cuerpo normal; `:412-430` consume texto/buffer completo.
- **Esperado:** `timeoutMs` limita la operación HTTP completa, incluyendo leer la respuesta.
- **Real:** cuando `fetch` resuelve cabeceras, el abort timer se limpia antes de `response.text()` / `arrayBuffer()`. Si el cuerpo se demora o queda trabado, no se aborta y la promesa excede el timeout; el `durationMs` incluye solo hasta el momento posterior, pero no impone límite.
- **Reproducción:** `bun evidence/gitlab/repro-timeout-body.ts` desde raíz del snapshot. Configura 5 ms y un `text()` que tarda 80 ms.
- **Resultado:** `{"elapsedMs":82,"aborted":false,"result":{"ok":true}}`. Log: `evidence/gitlab/repro-timeout-body.log`.
- **Impacto:** herramientas bloqueadas durante tiempo arbitrario pese al timeout configurado; ocupa worker/modelo y puede prolongar llamadas remotas. También permite respuestas que nunca terminan.
- **Causa:** lifecycle del timer termina al resolverse `fetchFn`, no al terminar consumo/cancelación del body.
- **Corrección mínima:** mantener activo timeout/abort hasta completar body parse, y cancelar/liberar stream en timeout.
- **Regresión:** fixture de body que no termina y fixture que tarda > timeout; ambas deben devolver error `timeout` dentro del límite, con señal abortada. Caso rápido debe aprobar.
- **Confianza:** alta: reproducción sin red, usando cliente real y fake response transport.
- **Relación:** nuevo.

### GLAB-03 — P2 — `maxBytes` no limita la descarga/materialización

- **Estado:** confirmado por cadena estática y conducta del test existente. **Componente:** `gitlab_artifacts` y cliente HTTP.
- **Ubicación:** `plugins/gitlab/src/lib/tools/shared.ts:1817-1843` solicita `ArrayBuffer` completo y solo aplica `maxBytes` al `slice` escrito; `plugins/gitlab/src/lib/client.ts:412-423` llama a `response.arrayBuffer()` sin límite.
- **Esperado:** el límite anunciado previene descargas grandes y memoria excesiva.
- **Real:** el servidor puede enviar un archivo arbitrariamente grande; Bun lo almacena entero en `ArrayBuffer` antes de que el handler recorte lo escrito. El test `tools.spec.ts` 442-479 usa un payload de 10 bytes y demuestra 4 bytes en disco, pero no comprueba el límite de red/memoria.
- **Reproducción:** inspección de la cadena anterior; mock actual permite constatar que `request<ArrayBuffer>` entrega el buffer completo antes de `slice`. No se pidió ni realizó descarga remota real.
- **Impacto:** respuesta hostil o artefacto grande puede agotar memoria del proceso a pesar de `maxBytes` (máximo declarado 16 MiB); el tamaño en disco sí queda acotado.
- **Causa:** limitación posterior a la lectura completa, no lectura streaming limitada.
- **Corrección mínima:** leer stream incremental con contador y cancelar al superar límite, o verificar `Content-Length` como prechequeo junto con límite real de stream.
- **Regresión:** stream sintético que emite bloques sobre el máximo; verificar cancelación temprana, no acumulación completa y salida de truncamiento o error documentado.
- **Confianza:** alta por código y test, no se afirma impacto externo medido.
- **Relación:** nuevo y distinto de GLAB-01/02.

## Evidencia negativa, límites y simplificación

No observé en esta revisión filtración del token por contexto/recibos, reintentos de mutaciones, escrituras remotas sin `confirm:true` o registros mutables por defecto. Los tests existentes cubren esas propiedades en fixtures. No se probó proveedor real, auth real, cuotas, latencia de red, salida real MCP ni compatibilidad de distintos hosts. `plugins/gitlab/AGENT.md` declara escrituras en `.delendai/cache/gitlab`, mientras la instrumentación recibe `pluginCacheDir`; verificar esa ruta efectiva desde host sigue pendiente global, no es prueba aquí de divergencia.

Recomendación: preservar cliente/provider shared y separar `shared.ts` por dominio de recurso; centralizar timeout y límite de tamaño en transporte streaming; usar primitive de escritura contenida que rechace symlinks. KPI: 0 escrituras fuera del cache con fixtures de enlaces, timeout p95 ≤ configured timeout + 50 ms para cuerpo, y bytes recibidos ≤ límite + tamaño de chunk para artefactos.
