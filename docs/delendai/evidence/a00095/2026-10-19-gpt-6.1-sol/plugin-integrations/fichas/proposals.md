## Function and public contracts

The stable-declared plugin is implemented: it reads and changes proposal documents, maintains derived registry/SQL projections, plans slice work, manages claims/queues, delegates through host ports, records evidence/review, and exposes recovery/health plus worktree/branch views. Its actual entrypoint, public exports, API/resources, surface policies and all registered-tool source were read. It depends on core, state/proposals-sqlite, quality, error-reporting/logs, SDK and Zod; selected host/delegation and Git ports are required for their operations. This is broader than a self-contained task list.

Do not infer the live surface from stale manifest lists. Consolidated proposal_get has a documented compact/normal/full contract, but its detail branch always chooses the same builder (PROP-DETAIL01). Generated outputs lose nullable strings (D111 extension), which is a typing error distinct from a demonstrated SDK validation failure. requireValidateEvidence is not forwarded consistently (PROP-CONFIG01); the schema comment also says global terminal gates remain, so product policy must be settled before weakening enforcement. Public skipDfaForPlanClosure is stripped by the compatibility wrapper; advertising an internal-looking key is not proof of a public bypass.

## State authority, isolation and lifecycle

Documents are the declared authority; index JSON and SQLite are projections with source modes, semantic digests, fallback and refresh. Status/path/parser differences still break consumers: blockedByFor resolves beside the cache, canonical parser drops contains/closureGate before the real closure guard, and round-context fallback misses canonical status folders. The parser-to-guard fixture accepts an unfinished child; no actual terminal transition was executed.

Configured paths come through context and the source contains scoped readers, mutexes, atomic writes, readonly SQL and quarantine preservation. A mutex protecting one artifact is not one transaction covering claims, ownership table, queue and registry. The canonical public lock engine holds the outer file-table mutex; a helper-only check race does not prove a public double grant. Legacy GC can represent unreadable Git status as clean, admitting a force-removal plan conditional on a positive delivery verdict; no real removal was performed. Quarantine repair reads a proposals-relative path from the workspace root. Torn JSONL tail can absorb the next good append. Default bypass warnings interpolate the unredacted reason, reproduced only with synthetic data and an intercepted sink.

Review quorum derives standing approvals from the log, invalidates them on resubmission, rejects repeat reviewer names and distinguishes recorded approval from actual closure. Mixed carried-work attribution drops the submitter before deciding a unique maker (G61-PROP-SVC03); the local identity journal still records the actual submitter and can block self-approval. It is not a universal independence bypass. Review auto-close loses configured instance independence (PROP-REVIEW01). close_slice overwrites supplied exitCode with0 and uses a date-only freshness helper on some paths (PROP-EVIDENCE01); real red quality, review and other persistence gates still apply. The P1 classification prioritizes the invalid evidence authority; the fixture did not complete a public close.

Gate admission owns an expirable process registry but checks other live jobs without their deadlines (PROP-GATE01). Reattaching the expired job frees the slot in the control fixture. Lock-tool teardown starts asynchronous session-claim release without joining it; task-queue teardown awaits its own cleanup, so that promise cannot prove all lock writes ended. Returned MCP errors become successful loop-detector outcomes (PROP-LOOP01), unlike thrown-error controls. These are bounded caller traces/fixtures, not observed failures on every host.

## Costs and product judgment

The manifest declares12,400static definition bytes,2,100adaptive activation,3,200typical output, hard15,000 and warning13,500, measuredAt2026-08-25. These are **historical metadata**, not a fresh whole-plugin SDK measurement in this batch. Generated guidance lists historical per-tool schema weights; no billed tokens, provider spend or causal whole-task savings are inferred. PROP-DETAIL01 proves compact detail does not currently select the narrow projection; PROP-ROUND01/02 show why a smaller but incomplete context is not a successful optimization. Full current native/managed/adaptive task comparisons remain in the audit's explicit limits.

Proposed simplification: one canonical proposal parser/status/path contract for every projection; use the strict evidence validator rather than a second freshness authority; carry one configured independence policy into all lifecycle transitions; centralize timed gate admission/expiry and preserve unknown cleanliness. These consolidate current functions instead of adding another orchestration layer. Suggested regression measures: zero dropped plan children, zero failed evidence accepted as passing, zero unknown-cleanliness GC admissions, expired gates stop holding capacity without reattachment, identical semantic results across detail modes, and complete portfolio counts with absent projections.
