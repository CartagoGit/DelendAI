## Resultado de validación de esta tanda

Primera ejecución global en copia aislada: `bun run test --reporter=default --maxWorkers=4 --bail=0`, sin corte prematuro,1312,02s, exit1. Reportó2105 archivos (2089 pass,15 fail,1 skip) y16912 tests (16899 pass,5 fail,8 skip). Los fallos se clasificaron: la extracción por git archive no tenía metadatos Git; faltaban los enlaces instalados de tools y tools/docs-api (tokenizadores y TypeScript5 para la language-service); no fueron fallos nuevos de código demostrados.

Se dotó a la misma copia de Git independiente en el SHA exacto y se restauraron enlaces a dependencias ya instaladas, sin modificar fuentes ni instalar versiones nuevas. Reejecución de las15 suites afectadas:15 archivos,162 tests PASS, exit0 en52,61s. Esta cifra se solapa con la primera ejecución y **no se suma** como162 tests nuevos. No afirmo que haya existido una segunda ejecución global verde.

`bun run test:sqlite`:87 archivos,479 tests,477 pass/2 fail, exit1 en221,56s. Ambos fallos fueron el gate esperado al forzar `CI=true` sin `GITHUB_SHA` en fixtures con commits propios. Reejecución de esos dos archivos en entorno local normal (CI/GITHUB_ACTIONS/GITHUB_SHA ausentes):4 tests PASS, exit0 en4,41s. No se cambió el gate ni se falseó una evidencia CI para obtenerlo.

Logs íntegros y comandos exactos bajo `evidence/completion-root/`. No hubo credenciales de proveedor ni consumo de cuotas de proveedores. Las dependencias y Git restaurados son preparación del entorno de prueba, no correcciones de producto.

## Cómo decidir las próximas propuestas

1. **Primero integridad y trabajo perdido:** corregir rollback que borra Git, refs destino sobrescritas, identidad de claim y expiración/recuperación de propietarios. Un caso mínimo por defecto con procesos vivos/muertos controlados y recuperación tras fallo.
2. **Después contratos utilizables:** registrar una matriz de list/call por herramienta y modo, con resultado ordinario/error y dependencias ausentes. Una entrada válida que no puede usarse importa más que un contador de tools anunciadas.
3. **Después autoridad y veracidad de datos:** un lector nunca presenta unknown como cero; advertir parcialidad y procedencia. Cuotas, ahorro, salud, roadmap y logs deben identificar fuente, ventana y fecha.
4. **Después simplificación guiada por evidencia:** reutilizar ranker/loader/almacenes ya integrados; retirar caminos demostrablemente huérfanos; separar cuerpos de archivo grandes por invariantes existentes. No crear una capa nueva sólo para coordinar las anteriores.

KPI propuestos: cero concesiones incompatibles en100rondas con PID vivo; cero refs preexistentes modificadas sin compare-and-swap; cero datos fuera del ámbito de rollback;100% de tools listadas con llamada válida y error de contrato comprobados en native/managed/adaptive;100% de fuentes parciales/corruptas etiquetadas; comparar bytes, llamadas, relist, latencia y cumplimiento final en la misma tarea. No fijar un objetivo de USD real sin una observación que permita medirlo.
