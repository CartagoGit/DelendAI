# Agents and models

One page per agent and per model provider this project uses, generated by
`delendai agents show <id> --write`.

An agent's page is built from its public catalogue entry and from what the
agent says about itself when greeted over the Agent Client Protocol: its
version, how it logs in, what a prompt may carry and whether it resumes
sessions.

A model provider's page is built from its own entry in the model catalogue
(or from your declaration of it): the API family and URL it is reached
through, the variables its key is read from (by name, never a value), its
models and the date of the catalogue it was written for.

Nothing on a page is text delendai keeps about a vendor, and nothing about
the machine it was written on.

A page records what it was written for and is rewritten when that changes.
Notes written between the `delendai:person` markers survive every rewrite.
A page without the generated marker is yours and is never replaced.

Where the agents come from:

- the public [Agent Client Protocol registry](https://agentclientprotocol.com/registry),
  read in layers (configured sources, this machine's copy, the snapshot
  shipped with delendai);
- `agents[]` in `delendai.config.json` or your own file
  (`delendai agents add`);
- what this machine shows: executables on PATH, global packages and IDE
  extensions (`delendai agents list`). An executable that only looks like
  an agent is asked about once; `delendai agents answer <name> --yes|--no`
  answers it without a terminal.

Where the model providers come from:

- the public [models.dev](https://models.dev) catalogue, read in the same
  layers;
- `modelProviders[]` in `delendai.config.json` or your own file, in
  models.dev's own shape; a declaration replaces the catalogue's entry of
  the same id.
