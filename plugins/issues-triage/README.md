# @delendai/issues-triage

**INTERNAL-ONLY** issue triage bot for the mcp-vertex repository.

> This package is **not published** to npm (`"private": true`), is absent
> from every preset, absent from `PUBLISH_ORDER`, and absent from the
> first-party plugin index. It can only be loaded explicitly inside this
> monorepo.

It reads GitHub issues, classifies them mechanically, drafts a complete fix
proposal and replies on the issue — every comment carries a mandatory
machine-disclosure notice.

## Load it (monorepo only)

```bash
mcp-vertex --plugins=proposals,issues-triage
```

```jsonc
{
  "plugins": {
    "proposals": {},
    "issues-triage": { "options": { "repo": "CartagoGit/delendai" } }
  }
}
```

Without `proposals` in the same load set, the server refuses to boot
(`dependsOn`). Without `repo`, zero tools register and a
`issues-triage-needs-repo` knowledge entry explains the fix.

## Tools

| Tool | Purpose |
|---|---|
| `<prefix>_triage_list` | List open issues on the watched repo. |
| `<prefix>_triage_run` | Analyse one issue, draft a fix proposal (optionally write it under `proposals/ready/` with an id from the shared proposals counter), and post an automated reply. |
| `<prefix>_triage_comment` | Post an automated progress/update comment (machine-disclosure notice prepended). |

## Machine disclosure

Every comment posted by this plugin starts with:

> 🤖 **Automated response** — this comment was generated by
> `@delendai/issues-triage`, the internal mcp-vertex issue bot.
> It performs mechanical triage; a human confirms before any fix ships.

## Design notes

- **No LLM inside the server.** Triage is pure keyword classification
  (`src/lib/analysis.ts`); the host decides what to execute.
- **Shared proposal counter.** `triage_run` allocates proposal ids via
  `allocateNextProposalId` from `@delendai/proposals`, so generated
  proposals stay in lockstep with the rest of the workflow.
- **Injectable `gh` seam.** All GitHub calls go through an injectable exec
  wrapping the host's authenticated `gh` CLI; the plugin never stores or
  prompts for a PAT.
